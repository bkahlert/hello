## Build prerequisites

- **JDK 11** (Liberica 11.0.19). Newer JDKs break Gradle 8.2.1 with a cryptic `What went wrong: 25.0.2`-style error.
  Set `JAVA_HOME=/Users/bkahlert/Library/Java/JavaVirtualMachines/liberica-11.0.19` before running anything.
  In IntelliJ: Settings → Build Tools → Gradle → Gradle JVM.

## Composite build layout

Top-level [settings.gradle.kts](settings.gradle.kts) aggregates every module via `includeBuild`. Tasks in
included builds are reached with their composite path, e.g. `:aws-lambdas:userinfo-api-handlers:shadowJar`,
not `:userinfo-api-handlers:shadowJar`.

## Static assets in Kotlin/JS

Files in `src/jsMain/resources/` of any module ship next to `index.html` in the app distribution.
The `kotlin-js-browser-application` convention plugin
([build-logic/kotlin-project/.../com.bkahlert.kotlin-js-browser-application.gradle.kts](build-logic/kotlin-project/src/main/kotlin/com.bkahlert.kotlin-js-browser-application.gradle.kts))
extracts non-metadata files from every `.klib` on the `jsRuntimeClasspath` into the app's `processedResources`,
so library-provided assets (e.g. [nyancat.svg](libs/hello-libs/hello-app/src/jsMain/resources/nyancat.svg))
reach the bundle. Reference them as relative URLs (`Uri("nyancat.svg")`).

## Deploying to prod

`aws-cdk/app/deploy-to-prod.sh` does **not** build any artifacts — it only runs `cdk deploy`. CDK reads from
disk at synth time:

- `apps/web-app/build/distributions/` — site assets
- `aws-lambdas/userinfo-api-handlers/build/libs/userinfo-api-handlers-all.jar` — user-info Lambda
- `aws-lambdas/userprops-api-handlers/build/libs/userprops-api-handlers-all.jar` — user-props Lambda

**Always rebuild before deploying** or stale artifacts ship:

```bash
JAVA_HOME=/Users/bkahlert/Library/Java/JavaVirtualMachines/liberica-11.0.19 ./gradlew \
  :aws-lambdas:userinfo-api-handlers:shadowJar \
  :aws-lambdas:userprops-api-handlers:shadowJar \
  :web-app:jsBrowserDistribution
```

**Validate with `cdk diff` first.** Run from `aws-cdk/app/`:

```bash
cd aws-cdk/app
JAVA_HOME=…liberica-11.0.19 AWS_PAGER="" cdk diff --profile prod
```

When the lambdas haven't actually changed, consider backing up the existing jars before rebuilding —
shadowJar output isn't reproducible (Kotlin/Gradle bumps cause hash drift even with identical source),
so a backup gives you a known-good fallback that matches what's currently deployed.

## AWS CLI quirks

- AWS CLI v2 fails non-interactively with `Errno 22 Invalid argument` if run from a shell with broken
  TTY assumptions (e.g. some zsh autocompletion setups). Workaround: set `AWS_PAGER=""` and prefer
  running from an interactive terminal.
- The deploy script sets `AWS_PROFILE=…` without `export`. Only the `cdk --profile`/`aws --profile`
  invocations see it; the Gradle subprocess relies on `CDK_DEFAULT_ACCOUNT`/`CDK_DEFAULT_REGION`
  forwarded by the CDK CLI.

## environment.json

Each app's `apps/<app>/src/jsMain/resources/environment.json` is generated by the
[DownloadEnvironment](build-logic/aws/src/main/kotlin/com/bkahlert/aws/DownloadEnvironment.kt) Gradle task
from CDK stack outputs, but **is committed** to git (existing convention, see `apps/web-app/environment.json`).
This means a fresh deploy can re-dirty the working tree; that's expected.
